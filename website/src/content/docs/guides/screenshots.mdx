Manage your App Store screenshots from capture to upload, including local automation workflows.

## Overview

The CLI provides two screenshot workflows:

1. **App Store Workflow**: Upload and manage screenshots in App Store Connect
2. **Local Automation**: Capture, frame, review, and prepare screenshots locally

## App Store Screenshot Management

The commands below upload screenshots directly to an app version. To store images
and videos independently and reuse them across version, custom product page,
optimization treatment, and event localizations, see the [Asset Library guide](/guides/asset-library).

### Understanding Screenshot Requirements

View required screenshot sizes for App Store submission:

```bash
asc screenshots sizes
```

For the full matrix including all device types:

```bash
asc screenshots sizes --all
```

<Note>
  For most iOS submissions, you need:

  * One iPhone set: `IPHONE_65` (6.5" display)
  * One iPad set: `IPAD_PRO_3GEN_129` (12.9" iPad Pro 3rd gen)

  The App Store will automatically scale these to other sizes.

  Starting April 2027, submissions of apps built with the iOS 27.1 SDK or later also need an iPhone Duo set: `IPHONE_DUO` (`APP_IPHONE_DUO`). Run `asc screenshots sizes --display-type "APP_IPHONE_DUO"` for its sizes.
</Note>

### Upload Screenshots

<Steps>
  <Step title="Prepare screenshot files">
    Export RGB PNG or JPEG images without alpha channels or transparency.
    `asc screenshots validate` reports PNG alpha channels and transparency as
    `alpha_channel` errors, and screenshot and Asset Library image uploads
    reject them before reserving an upload. Even an alpha channel whose pixels
    are all opaque must be removed when exporting.

    Organize screenshots by device type:

    ```
    screenshots/
    ├── iphone/
    │   ├── 01-home.png
    │   ├── 02-features.png
    │   └── 03-settings.png
    └── ipad/
        ├── 01-home.png
        ├── 02-features.png
        └── 03-settings.png
    ```
  </Step>

  <Step title="Upload iPhone screenshots">
    Select the localization with the app, version string, and locale. No
    localization ID lookup is needed:

    ```bash
    asc screenshots upload \
      --app "YOUR_APP_ID" \
      --version "1.2.3" \
      --locale "en-US" \
      --path "./screenshots/iphone" \
      --device-type "IPHONE_65" \
      --concurrency 4
    ```

    With `--locale`, `--path` points directly at that locale's screenshots.
    The version must already have an `en-US` localization; otherwise the
    command fails and lists the locales the version has.

    Uploads within one screenshot set are bounded to four concurrent requests
    by default. Use `--concurrency 1` for serial uploads or any value through
    `8` when the API and network can sustain more fan-out; output ordering stays
    deterministic.
  </Step>

  <Step title="Upload iPad screenshots">
    ```bash
    asc screenshots upload \
      --app "YOUR_APP_ID" \
      --version "1.2.3" \
      --locale "en-US" \
      --path "./screenshots/ipad" \
      --device-type "IPAD_PRO_3GEN_129"
    ```
  </Step>
</Steps>

If you already have a version localization ID, `--version-localization
"LOCALIZATION_ID"` uploads to it directly. `asc localizations list --app
"YOUR_APP_ID" --version "1.2.3"` shows each localization's ID.

### Device Types

Common device types for screenshots:

**iPhone:**

* `IPHONE_65` - 6.5" display (iPhone 14 Plus, etc.)
* `IPHONE_55` - 5.5" display (iPhone 8 Plus)
* `IPHONE_40` - 4" display (iPhone SE 1st gen)

**iPad:**

* `IPAD_PRO_3GEN_129` - 12.9" iPad Pro (3rd gen)
* `IPAD_PRO_129` - 12.9" iPad Pro (1st/2nd gen)
* `IPAD_105` - 10.5" iPad Pro
* `IPAD_97` - 9.7" iPad

**Apple Watch:**

* `APPLE_WATCH_SERIES_7` - 45mm Series 7
* `APPLE_WATCH_SERIES_4` - 44mm Series 4
* `APPLE_WATCH_SERIES_3` - 42mm Series 3

**Mac:**

* `DESKTOP`

**Apple TV:**

* `APPLE_TV`

### List Existing Screenshots

```bash
asc screenshots list --version-localization "LOCALIZATION_ID"
```

Filter client-side by device type:

```bash
asc screenshots list \
  --version-localization "LOCALIZATION_ID" \
  --output json | jq '.data[] | select(.attributes.displayType == "IPHONE_65")'
```

### Download Screenshots

Download all screenshots for a localization:

```bash
asc screenshots download \
  --version-localization "LOCALIZATION_ID" \
  --output-dir "./downloaded-screenshots"
```

### Delete Screenshots

Delete a specific screenshot:

```bash
asc screenshots delete --id "SCREENSHOT_ID" --confirm
```

<Warning>
  Deleting screenshots is permanent. Download backups before deleting.
</Warning>

### Complete Local Workflow

<Steps>
  <Step title="Capture screenshots from simulator">
    Launch your app in iOS Simulator, then capture screenshots:

    ```bash
    asc screenshots capture \
      --bundle-id "com.example.myapp" \
      --name "home-screen" \
      --output-dir "./screenshots/raw"
    ```

    This captures from the currently running simulator.
  </Step>

  <Step title="Frame screenshots with device bezel">
    Add device frame around raw screenshots:

    ```bash
    asc screenshots frame \
      --input "./screenshots/raw/home-screen.png" \
      --device "iphone-air" \
      --output-dir "./screenshots/framed"
    ```

    See available device frames:

    ```bash
    asc screenshots list-frame-devices
    ```
  </Step>

  <Step title="Generate HTML review gallery">
    Create an HTML page to review all screenshots:

    ```bash
    asc screenshots review-generate \
      --framed-dir "./screenshots/framed" \
      --output-dir "./screenshots/review"
    ```
  </Step>

  <Step title="Open review in browser">
    ```bash
    asc screenshots review-open --output-dir "./screenshots/review"
    ```

    This opens a browser with an interactive gallery for review.
  </Step>

  <Step title="Approve screenshots">
    Mark screenshots as ready for upload:

    ```bash
    asc screenshots review-approve \
      --all-ready \
      --output-dir "./screenshots/review"
    ```

    Or approve selectively in the browser UI.
  </Step>

  <Step title="Preview uploads from approved screenshots">
    Build a deterministic upload plan from the approved review artifacts:

    ```bash
    asc screenshots plan \
      --app "123456789" \
      --version "1.2.3"
    ```
  </Step>

  <Step title="Apply the approved upload plan">
    Apply the reviewed upload plan explicitly:

    ```bash
    asc screenshots apply \
      --app "123456789" \
      --version "1.2.3" \
      --confirm
    ```
  </Step>
</Steps>

### Screenshot Plan Automation

Define a complete screenshot plan in `.asc/screenshots.json`:

```json
{
  "bundle_id": "com.example.myapp",
  "device_types": ["iphone-air", "ipad-pro-129"],
  "locales": ["en-US", "es-ES", "ja"],
  "screenshots": [
    {
      "name": "home",
      "description": "Home screen showing main features",
      "device_type": "iphone-air"
    },
    {
      "name": "feature-detail",
      "description": "Detailed feature view",
      "device_type": "iphone-air"
    },
    {
      "name": "settings",
      "description": "Settings and customization",
      "device_type": "iphone-air"
    }
  ],
  "output_dirs": {
    "raw": "./screenshots/raw",
    "framed": "./screenshots/framed",
    "review": "./screenshots/review"
  }
}
```

Run the entire workflow:

```bash
asc screenshots run --plan .asc/screenshots.json
```

### Available Frame Devices

List supported devices for framing:

```bash
asc screenshots list-frame-devices --output json
```

Supported devices:

* iPhone: `iphone-air` (default), `iphone-17-pro`, `iphone-17-pro-max`, `iphone-16e`, `iphone-17`
* iPad: `ipad-pro-13`, `ipad-pro-11`, `ipad-air-13`, `ipad-air-11`, `ipad-mini`
* Apple Watch: `watch-series-11`, `watch-ultra-3`
* Apple TV: `apple-tv`
* Mac: `mac` (canvas without a bezel)

Frame each device from a capture of the same screen shape, such as a 422x514
Apple Watch Ultra 3 capture for `watch-ultra-3`. When an input's aspect ratio
differs from the device screen by more than 2%, `asc screenshots frame` prints a
warning on stderr, because the image is letterboxed inside the screen.

Native simulator captures from `xcrun simctl io <udid> screenshot` fill the
frame without that warning:

| Frame device | Simulator capture | Size |
| --- | --- | --- |
| `watch-series-11` | Apple Watch Series 11 or 12 (46mm) | 416x496 |
| `watch-ultra-3` | Apple Watch Ultra 3 or 4 (49mm) | 422x514 |
| `apple-tv` | Apple TV 4K | 3840x2160 |

```bash
xcrun simctl io "$WATCH_UDID" screenshot ./screenshots/raw/watch-home.png
asc screenshots frame --input ./screenshots/raw/watch-home.png --device watch-ultra-3 \
  --title "Roll the die" --text-position bottom
```

Each device entry lists its `frameColors`; pass one with `--frame-color`. See [Frame Screenshots](/commands/screenshots#frame-screenshots) for the full device and color matrix.

To frame a whole directory and retry only failed inputs on the next run:

```bash
asc screenshots frame --input-dir ./screenshots/raw --output-dir ./screenshots/framed \
  --device ipad-air-13 --frame-color blue --title "Plan every trip" --resume
```

To keep captions legible on a busy or light background and use a brand font file that is not installed on the machine (for example, a CI runner), add a text box and pass the font file to `--font`:

```bash
asc screenshots frame --input-dir ./screenshots/raw --output-dir ./screenshots/framed \
  --device iphone-air --title "Plan every trip" --bg-color "#f2c14e" \
  --font ./brand/Brand-Bold.ttf --text-box --text-box-color "#1b3a5bcc"
```

Per-file box settings go in `--overlay-config` entries as `textBox`, `textBoxColor`, `textBoxPadding`, and `textBoxRadius`. See [Frame Screenshots](/commands/screenshots#frame-screenshots) for the defaults and validation rules.

Large batches are CPU-bound. Add `--parallel-workers 4` (up to your CPU count) to render four inputs at once; the receipt order and `--resume` behavior stay the same.

## Complete Screenshot Workflow Example

Here's a complete workflow for managing screenshots:

```bash
#!/bin/bash
set -e

# Configuration
export ASC_APP_ID="YOUR_APP_ID"
VERSION="1.2.3"
BUNDLE_ID="com.example.myapp"

# 1. Check the version's localizations
asc localizations list --app "$ASC_APP_ID" --version "$VERSION" --output table

# 2. Create directories
mkdir -p screenshots/{raw,framed,iphone,ipad}

# 3. Capture screenshots (requires simulator running)
echo "Launch your app in iOS Simulator and press enter..."
read

for screen in home features settings details; do
  echo "Navigate to $screen screen and press enter..."
  read
  asc screenshots capture \
    --bundle-id "$BUNDLE_ID" \
    --name "$screen" \
    --output-dir "./screenshots/raw"
done

# 4. Frame screenshots
echo "Framing screenshots..."
for raw_file in screenshots/raw/*.png; do
  filename=$(basename "$raw_file")
  asc screenshots frame \
    --input "$raw_file" \
    --device "iphone-air" \
    --output-path "./screenshots/framed/$filename"
done

# 5. Copy to upload directories
cp screenshots/framed/*.png screenshots/iphone/

# 6. Upload to App Store Connect
echo "Uploading iPhone screenshots..."
asc screenshots upload \
  --app "$ASC_APP_ID" \
  --version "$VERSION" \
  --locale "en-US" \
  --path "./screenshots/iphone" \
  --device-type "IPHONE_65"

echo "Screenshots uploaded successfully!"

# 7. Verify upload
asc screenshots list --app "$ASC_APP_ID" --version "$VERSION" --locale "en-US"
```

If an upload stops partway through, the command prints a failure artifact path like
`.asc/reports/screenshots-upload/failures-123.json`. Resume the remaining files with:

```bash
asc screenshots upload --resume ".asc/reports/screenshots-upload/failures-123.json"
```

## Preview Videos

Upload app preview videos:

### Upload Preview Video

```bash
asc video-previews upload \
  --version-localization "LOCALIZATION_ID" \
  --path "./previews/app-preview.mp4" \
  --device-type "IPHONE_65"
```

Add `--time-code "00:00:05:00"` to set the poster frame after Apple finishes processing each video. If that fails or times out, the command exits non-zero but keeps the delivered preview, so you can retry with `asc video-previews set-poster-frame`.

### Preview Video Requirements

* **Format**: H.264 or HEVC codec, .mov or .mp4
* **Duration**: 15-30 seconds
* **Resolution**: Matches device screenshot size
* **File size**: Up to 500 MB
* **Aspect ratio**: Matches device (typically 16:9 or device aspect)

## Multi-Locale Screenshot Workflow

For apps with multiple localizations, you can now fan out one upload across
all matching locale directories:

```bash
asc screenshots upload \
  --app "YOUR_APP_ID" \
  --version "1.2.3" \
  --path "./screenshots" \
  --device-type "IPHONE_65"
```

Recommended directory layout:

```text
screenshots/
  en-US/
    iphone/
      01-home.png
      02-settings.png
  fr-FR/
    iphone/
      01-home.png
  ja/
    iphone/
      01-home.png
```

The command resolves the app store version, fetches its version localizations,
and uploads each locale subtree to the matching remote localization. It only
includes files whose dimensions match the selected `--device-type`, so mixed
iPhone/iPad locale trees are safe as long as each locale contains the slot
you are uploading. A device-rooted layout such as `screenshots/iphone/en-US`
also works when `--path` points at `./screenshots/iphone`.

For CI or large locale batches, save the printed failure artifact as a workflow
artifact so a rerun can continue with
`asc screenshots upload --resume <artifact>`.

## Troubleshooting

### "Invalid image dimensions"

**Problem**: Screenshot dimensions don't match the device type.

**Solution**: Verify required dimensions:

```bash
asc screenshots sizes
```

Ensure your images match exactly:

* iPhone 6.5": 1242 x 2688 pixels
* iPad Pro 12.9": 2048 x 2732 pixels

### "Capture failed - no simulator running"

**Problem**: `asc screenshots capture` requires a running simulator.

**Solution**:

1. Launch iOS Simulator
2. Open your app in the simulator
3. Run the capture command

### "Frame device not found"

**Problem**: Invalid device name for framing.

**Solution**: List available devices:

```bash
asc screenshots list-frame-devices
```

Use exact device names from the output.

### "Upload failed - file too large"

**Problem**: Image file size exceeds limits.

**Solution**: Optimize images:

```bash
# Using ImageMagick
mogrify -quality 85 -resize '1242x2688>' screenshots/*.png

# Using pngquant for compression
pngquant --quality=80-95 screenshots/*.png
```

## Best Practices

1. **Use consistent naming**: Name screenshots clearly (`01-home.png`, `02-features.png`)

2. **Optimize file sizes**: Compress screenshots to reduce upload time while maintaining quality

3. **Follow Apple guidelines**:
   * No UI chrome (status bars are optional)
   * Show actual app content
   * Use device-appropriate assets

4. **Localize screenshots**: Create locale-specific screenshots showing localized UI

5. **Test on real devices**: Capture from actual devices when possible for best quality

6. **Version control**: Keep screenshot sources in git for easy updates

7. **Automate where possible**: Script repeated capture, framing, and upload steps with the local workflow tools

8. **Review before upload**: Always review screenshots in context before uploading to App Store Connect
