# Output Formats

> Control how the CLI renders command results with TTY-aware defaults and multiple output formats.

The App Store Connect CLI supports multiple output formats and automatically adapts to your environment.

## Format Options

All commands that return data support three output formats:

* **`json`** - Machine-parseable JSON (default for non-interactive contexts)
* **`table`** - Human-readable table (default for interactive terminals)
* **`markdown`** - Markdown-formatted tables

## TTY-Aware Defaults

The CLI automatically detects whether it's running in an interactive terminal:

```bash  theme={null}
# Interactive terminal (TTY detected)
asc apps list
# Output: table format

# Piped or CI environment (no TTY)
asc apps list | jq '.data[0].id'
# Output: json format
```

This behavior follows the principle: **human-friendly in terminals, machine-friendly in pipes and scripts**.

## Explicit Format Selection

Override the default with the `--output` flag:

```bash  theme={null}
# Force JSON in an interactive terminal
asc apps list --output json

# Force table format in a script
asc apps list --output table

# Markdown format (alias: md)
asc apps list --output markdown
```

## Environment Variable

Set a default format across all commands with `ASC_DEFAULT_OUTPUT`:

```bash  theme={null}
export ASC_DEFAULT_OUTPUT=json
asc apps list  # Uses JSON even in interactive terminals

# Explicit --output flag always overrides ASC_DEFAULT_OUTPUT
asc apps list --output table
```

Valid values: `json`, `table`, `markdown`, `md`

<Note>
  The `--output` flag always takes precedence over `ASC_DEFAULT_OUTPUT` and TTY detection.
</Note>

## Pretty-Printing JSON

For human-readable JSON output, use the `--pretty` flag:

```bash  theme={null}
asc apps list --output json --pretty
```

Example output:

```json  theme={null}
{
  "data": [
    {
      "id": "123456789",
      "type": "apps",
      "attributes": {
        "name": "My App",
        "bundleId": "com.example.app"
      }
    }
  ]
}
```

<Warning>
  The `--pretty` flag only works with `--output json`. Using `--pretty` with `table` or `markdown` returns an error.
</Warning>

## Sensitive Values

Secrets are withheld from output by default. Commands that read or write App
Store or TestFlight review information replace a non-empty
`demoAccountPassword` with `(redacted)` before rendering, in every format:

```bash  theme={null}
asc review details-get --id "DETAIL_ID" --output json
```

```json  theme={null}
{"data":{"type":"appStoreReviewDetails","id":"DETAIL_ID","attributes":{"demoAccountName":"reviewer@example.com","demoAccountPassword":"(redacted)","demoAccountRequired":true}}}
```

This applies to `asc review details-get`, `asc review details-for-version`,
`asc review details-create`, `asc review details-update`,
`asc testflight review view`, `asc testflight review edit`, and
`asc migrate import` (including `--dry-run`).

Redaction affects only what is printed. Passwords you pass with
`--demo-account-password` are still sent to App Store Connect, and
`asc migrate import` still uploads and compares the real value read from
`review_information/demo_password.txt`.

### Opting in with `--include-sensitive`

When you genuinely need the returned password — for example to verify a
rotation — add `--include-sensitive`:

```bash  theme={null}
asc review details-get --id "DETAIL_ID" --output json --include-sensitive
```

The flag applies to that one invocation only, defaults to `false`, and has no
environment-variable equivalent, so a secret can never become visible because
of ambient configuration. Each use writes a warning to stderr because printed
secrets persist in shell history, CI logs, and terminal scrollback.

<Warning>
  Before this change, `demoAccountPassword` was emitted verbatim in JSON output,
  and `asc migrate import` also printed it in table and Markdown output. If a
  script depended on reading the password back, add `--include-sensitive`
  explicitly and make sure the surrounding logs are not retained.
</Warning>

## Format Examples

### Table Format

```bash  theme={null}
asc apps list --limit 2 --output table
```

```
ID          NAME        BUNDLE ID           SKU
123456789   My App      com.example.app     APP001
987654321   Other App   com.example.other   APP002
```

### JSON Format

```bash  theme={null}
asc apps list --limit 1 --output json
```

```json  theme={null}
{"data":[{"id":"123456789","type":"apps","attributes":{"name":"My App","bundleId":"com.example.app","sku":"APP001"}}]}
```

### Markdown Format

```bash  theme={null}
asc apps list --limit 2 --output markdown
```

```markdown  theme={null}
| ID        | NAME      | BUNDLE ID         | SKU    |
|-----------|-----------|-------------------|--------|
| 123456789 | My App    | com.example.app   | APP001 |
| 987654321 | Other App | com.example.other | APP002 |
```

## Implementation Details

Output format resolution follows this priority order:

1. **Explicit `--output` flag** (highest priority)
2. **`ASC_DEFAULT_OUTPUT` environment variable**
3. **TTY detection** (lowest priority)
   * TTY detected → `table`
   * No TTY → `json`

The CLI uses `term.IsTerminal()` to check stdout's file descriptor. This works correctly with:

* Pipes: `asc apps list | jq`
* Redirects: `asc apps list > output.json`
* CI environments: GitHub Actions, GitLab CI, Jenkins
* Docker containers (non-interactive)

## Format Registry

The CLI uses a type-safe output registry system (`internal/asc/output_registry.go`) that maps response types to rendering functions. This ensures:

* Consistent formatting across all commands
* Type-safe row extraction
* Automatic handling of single vs. list responses

Most commands automatically support all three formats without additional code.

## Piping Resource Links Back In

JSON reads print Apple's envelope unmodified, so every resource carries a
`links.self` URL. Webhook deliveries and other tooling hand the same URLs
around. The resource ID flags on the most-used commands accept that URL in
place of the bare ID, so a `links.self` value can be passed straight back:

```bash
# Extract the self-link of the latest build and pass it to builds info
LINK=$(asc builds list --app 123456789 --limit 1 --output json | jq -r '.data[0].links.self')
asc builds info --build-id "$LINK"

# Equivalent to
asc builds info --build-id 2f1a3c4d-...
```

Rules:

* Only `https://api.appstoreconnect.apple.com/v<n>/<type>/<id>` URLs are
  accepted. Relationship and related-resource paths
  (`/v1/builds/<id>/relationships/betaGroups`) are rejected so the intent
  stays explicit.
* A flag that names one resource type rejects a link of another type
  (`--build-id` with an `appStoreVersions` link) with a usage error, exit code
  `2`, before authentication or any request.
* Bare IDs, bundle identifiers, product IDs, and names keep working
  unchanged.

Flags covered today: every single-value `--<resource>-id` flag that names an
App Store Connect API resource, including `--build-id`, `--version-id`,
`--webhook-id`, `--event-id`, `--experience-id`, `--custom-page-id`,
`--experiment-id`, `--offer-code-id`, `--report-id`, `--run-id`,
`--merchant-id`, `--pass-type-id`, `--review-id`, `--category-id`,
`--mapping-id`, `--domain-id`, `--tester-id`, the Game Center ID flags, plus
`--app` (including `ASC_APP_ID`), `--submission-id`, `--info-id`,
`--localization-id`, `--subscription-id`, `--iap-id`, the `--id`/`--group`
flags on `testflight groups`, `--id` on `apps`, `subscriptions`, `iap`, and
`bundle-ids`, and `--bundle` on `bundle-ids capabilities`.

Still bare-ID only, on purpose: comma-separated ID filters (they take a list,
not one URL), `asc web` flags (Developer Portal and Iris IDs have no API
self-link), flags that take an identifier rather than a resource ID (bundle
identifiers, product IDs, Game Center vendor identifiers), credentials and
local identifiers (the `--key-id` and `--issuer-id` flags on `asc auth`, the
`--device-id` flag on `asc xcode install`, and the `asc storekit` flags), and
the few flags whose resource type depends on another flag (`--item-id` on
`asc review items add`, which follows `--item-type`, and `--product-id` on
`asc iap promoted-purchases create`, which follows `--product-type`).
