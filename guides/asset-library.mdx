# Asset Library

> Upload, inspect, and reuse App Store images and videos

Asset Library stores media independently of an app version. Uploading creates a library asset; a placement assigns that asset to a localization. App Review and storefront publication have their own requirements.

<Note>
  Apple's OpenAPI 4.5.1 documents the core Asset Library and placement resources. Apple controls media compatibility, asset eligibility, and permissions. Successful upload or placement requests do not establish App Review approval or storefront publication.
</Note>

## Find a library and inspect its assets

```bash theme={null}
asc asset-library view --app APP_ID
asc asset-library images list --library-id LIBRARY_ID --paginate
asc asset-library videos list --library-id LIBRARY_ID --paginate
asc asset-library specs
```

Use `images view --id IMAGE_ID` or `videos view --id VIDEO_ID` to inspect one asset. Use `images placements --id IMAGE_ID` or `videos placements --id VIDEO_ID` to inspect its usage. JSON reads preserve Apple's resource envelope, including unknown fields. Collection commands support `--limit`, `--next`, and `--paginate`; `--output table` or `--output markdown` provides human-readable output.

### Filter and sort collections

```bash theme={null}
asc asset-library images list --library-id LIBRARY_ID \
  --category CREATIVE_ASSETS --state APPROVED --sort referenceName
asc asset-library videos list --library-id LIBRARY_ID \
  --state FAILED --sort=-lastModifiedDate --paginate
asc asset-library images list --library-id LIBRARY_ID --spec-id SPEC_ID
asc asset-library images list --library-id LIBRARY_ID \
  --reference-name "Summer header" --sort=-createdDate
asc asset-library videos list --library-id LIBRARY_ID --id VIDEO_ID --sort createdDate
```

Filter by `--category`, `--state`, `--spec-id`, `--reference-name`, or `--id`. Filters and sort fields accept comma-separated values. Supported sort fields are `referenceName`, `createdDate`, and `lastModifiedDate`; prefix a field with `-` for descending order. Reference names are internal App Store Connect names. Apple validates state values and filter support. The CLI does not expose an `--archived` filter.

These filters belong to image/video `list` commands. Do not combine them or a library selector with `--next`: use Apple's next URL unchanged. `--paginate` follows those URLs automatically.

## Upload images and videos

The default upload category is `CREATIVE_ASSETS`, for headers, search creative media, and events. Use `APP_SCREENSHOTS_AND_PREVIEWS` for media showing your app in use.

```bash theme={null}
asc asset-library images upload --library-id LIBRARY_ID --file ./header.png
asc asset-library videos upload --library-id LIBRARY_ID --file ./header.mp4
asc asset-library images upload --library-id LIBRARY_ID \
  --file ./duo-screenshot.png --category APP_SCREENSHOTS_AND_PREVIEWS
asc asset-library videos upload --library-id LIBRARY_ID \
  --file ./duo-preview.mp4 --category APP_SCREENSHOTS_AND_PREVIEWS
```

Image files must meet the selected category's media specifications. Screenshots and creative images cannot contain an alpha channel or transparency, even when all pixels appear opaque.

Video upload requires `ffprobe` from FFmpeg and a regular, nonempty `.mp4`, `.m4v`, or `.mov` file within the upload size limit. Before reservation, the CLI checks the staged file against Apple's current reference specifications: category, dimensions, aspect ratio, duration, frame rate, required audio, extension, container MIME type, and file size. Apple's processing remains authoritative for codec acceptance.

[Creative asset specifications](https://developer.apple.com/help/app-store-connect/reference/app-information/creative-assets-specifications) distinguish header/search videos, typically 5–30 seconds at 30 or 60 fps, from app previews. [App preview specifications](https://developer.apple.com/help/app-store-connect/reference/app-information/app-preview-specifications) require 15–30 seconds and have their own delivery and encoding requirements. Check `asc asset-library specs` for the current reference data rather than treating these examples as a complete specification.

`ASC_UPLOAD_TIMEOUT` bounds upload and processing. Video uploads default to `30m`, because Apple commonly takes 10 to 15 minutes to process a video; images use the general `5m` default. Processing may continue after the command times out; increase the timeout when needed. A failure after reservation prints a partial receipt containing the asset ID. Inspect that ID with `asc asset-library videos view --id VIDEO_ID` (or `images view`) before retrying or deleting it; the CLI does not delete the reservation automatically.

Video transfer or a completed poster thumbnail does not prove the video is playable. Readiness requires the expected preparation state, a matched specification, and a usable video asset URL. Processing failures return an error with the reserved ID.

### iPhone Duo sizes

Duo screenshot sizes are **1398×2034** for the outer display and **2007×2853** for the inner display, with landscape counterparts. Apple's documented Duo app preview delivery sizes are **886×1920** or **1920×886**, which differ from the physical display sizes. Use the accepted preview delivery size when preparing a video.

See [screenshot specifications](https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications) and [app preview specifications](https://developer.apple.com/help/app-store-connect/reference/app-information/app-preview-specifications). Native asset placements use the `IPHONE_DUO_PROFILE` group.

## Manage asset names, lifecycle, and poster frames

```bash theme={null}
asc asset-library images rename --id IMAGE_ID --name "Summer header"
asc asset-library images archive --id IMAGE_ID --confirm
asc asset-library images unarchive --id IMAGE_ID
asc asset-library images delete --id IMAGE_ID --confirm
asc asset-library videos set-poster-frame --id VIDEO_ID --time-code 00:00:01:00
```

Videos also support `rename`, `archive`, `unarchive`, and `delete` with `--id`. The reference name is internal to App Store Connect.

Only approved assets can be archived. Archived assets cannot be used in new placements; restoring an asset makes it available for new uses, subject to Apple's checks. Apple validates whether an asset can be deleted based on its current state and usage. To remove an assignment while retaining the media, delete its placement instead.

Poster changes affect every placement using that library video. Poster frames cannot be edited after the asset is approved. `--time-code` accepts `HH:MM:SS:FF` or `HH:MM:SS.mmm`; the CLI does not interpret frame values as a particular playback frame rate.

Apple validates lifecycle eligibility. These commands do not submit assets for review.

## Reuse media in localized placements

Placement reads, creation, swaps, and deletion are available under four command groups. Reordering is available only for version, CPP, and PPO localizations:

| Context | Command group |
| --- | --- |
| App version localization | `asc localizations placements` |
| Custom product page localization | `asc product-pages custom-pages localizations placements` |
| Product page optimization treatment localization | `asc product-pages experiments treatments localizations placements` |
| In-App Event localization | `asc app-events localizations placements` |

Use the localization ID for the selected context, not its parent page, treatment, event, or version ID.

```bash theme={null}
asc localizations placements list --localization-id LOCALIZATION_ID \
  --include image,video --sort placementGroupPosition --paginate
asc localizations placements create --localization-id LOCALIZATION_ID \
  --image-id IMAGE_ID --placement-type PRODUCT_PAGE_HEADER_ASSET
asc localizations placements create --localization-id LOCALIZATION_ID \
  --video-id VIDEO_ID --placement-type APP_PREVIEW --placement-group IPHONE_DUO_PROFILE
asc app-events localizations placements create --localization-id EVENT_LOCALIZATION_ID \
  --image-id IMAGE_ID --placement-type EVENT_CARD_ASSET
```

Supply exactly one `--image-id` or `--video-id`. Screenshots require images; app previews require videos and an explicit device `--placement-group`. Header, search, and event creative media use `DEFAULT_PROFILE`. Header/search types are `PRODUCT_PAGE_HEADER_ASSET` and `APP_STORE_SEARCH_RESULTS_ASSET`. Events accept only `EVENT_CARD_ASSET` and `EVENT_DETAILS_PAGE_ASSET`.

Version localizations also support `IMESSAGE_APP_SCREENSHOT`. CPP and PPO creation do not support iMessage screenshot assignments. Apple validates media compatibility and available slots. Placement lists accept comma-separated type/group filters, related `image,video` inclusion, sorting, and pagination.

### Replace an existing placement

```bash theme={null}
asc product-pages custom-pages localizations placements swap \
  --localization-id CPP_LOCALIZATION_ID --placement-id OLD_PLACEMENT_ID \
  --image-id IMAGE_ID --placement-type PRODUCT_PAGE_HEADER_ASSET --confirm
```

`swap` uses a live-supported extension outside the OpenAPI 4.5.1 create schema to link the existing placement to its replacement in one request. It accepts an image or video of the same media type as the existing placement, sends no placement group, and requires `--confirm`. Apple validates the existing context, group, media, and editability. A failed swap does not trigger a separate deletion or fallback removal.

For an already-live version, Apple's website guides users through **Next → Publish** when selecting an approved replacement. The CLI's swap receipt does not promise storefront publication; no separate public publication command is available. New-version assets still follow the version's review and release workflow.

### Reorder and remove placements

```bash theme={null}
asc localizations placements reorder --localization-id LOCALIZATION_ID \
  --placement-group IPHONE_DUO_PROFILE --placement-ids FIRST_ID,SECOND_ID
asc localizations placements delete --id PLACEMENT_ID --confirm
asc localizations placements delete --placement-ids FIRST_ID,SECOND_ID --confirm
```

Reordering sends unique placement IDs in the requested order for version, CPP, or PPO localizations. Apple validates membership in the localization and group. Omitted placements are not deleted by the CLI. Event placement reordering is not supported.

Multiple removal uses sequential public DELETE requests. It is not atomic: processing stops at the first failure, prints a partial receipt with `deletedPlacementIds` and `failedPlacementId`, and returns a nonzero error. Earlier successful removals are not rolled back. Inspect current state before retrying an uncertain failure.

Placement deletion keeps the library media. IDs control removal; the command does not check that an ID belongs to the command group's localization or placement type.

## Review and publication

Upload, placement, reorder, and lifecycle commands do not submit App Review. The CLI supports `asc review items add` with `--item-type appAssetLibraryImages` or `appAssetLibraryVideos` and `--item-id` using Apple's documented review relationships. Live image/video review-item acceptance has not been independently verified. A [community image submission report](https://github.com/rorkai/App-Store-Connect-CLI/pull/2932#issuecomment-6013396808) reached `WAITING_FOR_REVIEW`; video acceptance and final asset approval remain unverified.

Separate asset review requires an approved app version. For the first version, include the assets with that version's submission. Assets assigned to a version, CPP, PPO test, or event are reviewed with that item; active submissions can restrict standalone submission. Apple's [standalone submission guide](https://developer.apple.com/help/app-store-connect/manage-submissions-to-app-review/submit-assets-from-asset-library) explains platform selection and eligibility.

This guide's examples stop before submitting review or publishing. A processed upload, an `ACTIVE` placement, or a successful swap is not evidence of App Review approval or live storefront content.
