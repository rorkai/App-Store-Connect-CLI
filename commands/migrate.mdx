# migrate

> Migrate metadata from/to fastlane format

Migrate metadata between fastlane's deliver tool and App Store Connect CLI.

## Quick Start

```bash  theme={null}
asc migrate import --app "APP_ID" --version-id "VERSION_ID" --fastlane-dir ./fastlane --confirm
asc migrate export --app "APP_ID" --version-id "VERSION_ID" --output-dir ./fastlane
asc migrate validate --fastlane-dir ./fastlane
```

App Clip default-experience files live under `metadata/<locale>/app_clip/` and `metadata/app_clip/action.txt`. App Preview videos live under `app_previews/<locale>/<device_type>/`. `asc metadata pull` and `asc metadata push` use this same canonical layout.

```bash theme={null}
asc migrate import --skip-app-clip --skip-previews --dry-run
```

## Subcommands

* `import` - Import metadata from fastlane directory structure
* `export` - Export metadata to fastlane directory structure
* `validate` - Validate fastlane metadata without uploading
* `metadata` - Bridge to `asc metadata` commands

## Commands

### migrate import

Import metadata from fastlane directory structure:

```bash  theme={null}
asc migrate import --app "APP_ID" --version-id "VERSION_ID" --fastlane-dir ./fastlane --dry-run
asc migrate import --app "APP_ID" --version-id "VERSION_ID" --fastlane-dir ./fastlane --confirm
```

`--confirm` is required unless `--dry-run` is set. When both are set, `--dry-run` wins and nothing is uploaded.

**Flags:**

* `--app` - App Store Connect app ID (or `ASC_APP_ID`)
* `--version-id` - App Store version ID (required unless Deliverfile app\_version + platform)
* `--fastlane-dir` - Path to fastlane directory (optional)
* `--dry-run` - Preview changes without uploading
* `--confirm` - Confirm uploading the imported metadata and screenshots (required unless `--dry-run`)
* `--skip-screenshots` - Skip screenshot discovery and upload
* `--allow-external-metadata` - Trust Deliverfile metadata paths and symlinks outside the selected Fastlane directory
* `--allow-external-screenshots` - Trust Deliverfile screenshot paths and symlinks outside the selected Fastlane directory
* `--allow-symlinked-deliverfile` - Trust and follow a symlinked Deliverfile
* `--include-sensitive` - Print secret values such as demo account passwords instead of redacting them
* `--output` - Output format: `json`, `table`, `markdown`
* `--pretty` - Pretty-print JSON output

**Fastlane directory structure:**

```
fastlane/
├── Deliverfile
├── metadata/
│   ├── en-US/
│   │   ├── name.txt            (App Info)
│   │   ├── subtitle.txt        (App Info)
│   │   ├── privacy_url.txt     (App Info)
│   │   ├── description.txt     (Version)
│   │   ├── keywords.txt        (Version)
│   │   ├── release_notes.txt   (Version)
│   │   ├── promotional_text.txt (Version)
│   │   ├── support_url.txt     (Version)
│   │   └── marketing_url.txt   (Version)
│   ├── review_information/
│   │   ├── first_name.txt
│   │   ├── last_name.txt
│   │   ├── email_address.txt
│   │   ├── phone_number.txt
│   │   ├── demo_user.txt
│   │   ├── demo_password.txt
│   │   ├── demo_required.txt
│   │   └── notes.txt
├── screenshots/
│   ├── en-US/
│   │   ├── iphone_65_1.png
│   │   └── ...
```

### migrate export

Export current App Store metadata to fastlane directory structure:

```bash  theme={null}
asc migrate export --app "APP_ID" --version-id "VERSION_ID" --output-dir ./fastlane
```

**Flags:**

* `--app` - App Store Connect app ID (or `ASC_APP_ID`)
* `--version-id` - App Store version ID (required)
* `--output-dir` - Output directory for fastlane structure (required)
* `--output` - Output format: `json`, `table`, `markdown`
* `--pretty` - Pretty-print JSON output

### migrate validate

Validate fastlane metadata without making any API calls:

```bash  theme={null}
asc migrate validate --fastlane-dir ./fastlane
asc migrate validate --fastlane-dir ./fastlane --output table
```

**Flags:**

* `--fastlane-dir` - Path to fastlane directory (required)
* `--allow-external-metadata` - Trust a metadata symlink outside the selected Fastlane directory
* `--output` - Output format: `json`, `table`, `markdown`
* `--pretty` - Pretty-print JSON output

**Character limits checked:**

* Description: 4000 characters
* Keywords: 100 characters
* What's New (release notes): 4000 characters
* Promotional Text: 170 characters
* Name: 30 characters
* Subtitle: 30 characters

Locale directories are checked against the App Store Connect locale catalog with
the same rule `migrate import` applies when it has to create a localization, so
a directory such as `metadata/nl` is reported as an error (`nl-NL` is the
supported code) instead of failing later during an import. `migrate import
--dry-run` performs the same check before it previews a plan.

`migrate validate` resolves its metadata directory exactly the way `migrate
import` does: a Deliverfile `metadata_path` wins over the conventional
`metadata/` directory, `skip_metadata` turns the check off, and an overridden
conventional directory is reported in `skipped`. Validating a directory the
import step never reads would green-light a tree the import then rejects.

## Deliverfile Support

The import command supports reading configuration from a `Deliverfile`:

```ruby  theme={null}
# Deliverfile
app_identifier "com.example.myapp"
app_version "1.2.3"
platform "ios"

skip_metadata false
skip_screenshots false
```

**Supported fields:**

* `app_identifier` - App bundle ID (used to resolve app ID)
* `app_version` - App version string (used to resolve version ID)
* `platform` - Platform: `ios`, `osx` (or `macos`), `appletvos` (or `tvos`), `xros` (or `visionos`)
* `skip_metadata` - Skip metadata import
* `skip_screenshots` - Skip screenshot import
* `metadata_path` - Metadata directory, resolved relative to the Deliverfile
* `screenshots_path` - Screenshots directory, resolved relative to the Deliverfile

`metadata_path` and `screenshots_path` win over the conventional `metadata/` and
`screenshots/` directories, including when `--fastlane-dir` selected the
Deliverfile. When a conventional directory exists but is not read, it is
reported in `skipped`. A Deliverfile path that points outside the selected
directory is rejected unless `--allow-external-metadata` or
`--allow-external-screenshots` is passed, and a Deliverfile path that does not
exist fails the command instead of falling back.

Both paths resolve relative to the Deliverfile, not to the project root.
`deliver` resolves them from the directory `fastlane` runs in, so a
`fastlane/Deliverfile` often carries a project-root-relative value that lands one
level too deep here:

```ruby  theme={null}
metadata_path "./fastlane/metadata"  # resolves to fastlane/fastlane/metadata; write "./metadata" instead
```

That run fails with the resolved path, and when the conventional
`fastlane/metadata` (or `fastlane/screenshots`) directory exists next to the
Deliverfile the error says so.

## Metadata Fields

### App Info (App-level)

* `name.txt` - App name
* `subtitle.txt` - App subtitle
* `privacy_url.txt` - Privacy policy URL

### Version (Version-level)

* `description.txt` - App description
* `keywords.txt` - Keywords (comma-separated)
* `release_notes.txt` - What's new / release notes
* `promotional_text.txt` - Promotional text
* `support_url.txt` - Support URL
* `marketing_url.txt` - Marketing URL

### Review Information

* `first_name.txt` - Contact first name
* `last_name.txt` - Contact last name
* `email_address.txt` - Contact email
* `phone_number.txt` - Contact phone
* `demo_user.txt` - Demo account username
* `demo_password.txt` - Demo account password
* `demo_required.txt` - Demo account required (true/false)
* `notes.txt` - Review notes

## Examples

### Import from Fastlane

```bash  theme={null}
# Preview import
asc migrate import \
  --app "123456789" \
  --version-id "abc123" \
  --fastlane-dir ./fastlane \
  --dry-run

# Import metadata
asc migrate import \
  --app "123456789" \
  --version-id "abc123" \
  --fastlane-dir ./fastlane \
  --confirm
```

### Export to Fastlane

```bash  theme={null}
asc migrate export \
  --app "123456789" \
  --version-id "abc123" \
  --output-dir ./fastlane
```

### Validate Before Import

```bash  theme={null}
# Validate fastlane metadata
asc migrate validate --fastlane-dir ./fastlane --output table

# If valid, import
if asc migrate validate --fastlane-dir ./fastlane --output json | jq -e '.valid'; then
  asc migrate import --app "APP_ID" --version-id "VERSION_ID" --fastlane-dir ./fastlane --confirm
fi
```

### Migrate from Fastlane to asc metadata

```bash  theme={null}
# Export from fastlane format
asc migrate export \
  --app "APP_ID" \
  --version-id "VERSION_ID" \
  --output-dir ./fastlane

# Import into asc metadata format
asc migrate metadata pull \
  --app "APP_ID" \
  --version "1.2.3" \
  --dir "./metadata"

# Now use asc metadata commands
asc metadata push --app "APP_ID" --version "1.2.3" --dir "./metadata" --dry-run
```

## Migration Workflow

### From Fastlane to asc

1. Validate current fastlane metadata:
   ```bash  theme={null}
   asc migrate validate --fastlane-dir ./fastlane
   ```

2. Import to App Store Connect:
   ```bash  theme={null}
   asc migrate import --app "APP_ID" --version-id "VERSION_ID" --fastlane-dir ./fastlane --confirm
   ```

3. Pull into asc metadata format:
   ```bash  theme={null}
   asc metadata pull --app "APP_ID" --version "1.2.3" --dir "./metadata"
   ```

4. Future updates use asc metadata:
   ```bash  theme={null}
   asc metadata push --app "APP_ID" --version "1.2.3" --dir "./metadata"
   ```

### From asc to Fastlane

1. Export current metadata:
   ```bash  theme={null}
   asc migrate export --app "APP_ID" --version-id "VERSION_ID" --output-dir ./fastlane
   ```

2. Use with fastlane:
   ```bash  theme={null}
   fastlane deliver
   ```

## Screenshot Import

The import command supports uploading screenshots from the fastlane directory:

```
screenshots/
├── en-US/
│   ├── iphone_65_1.png
│   ├── iphone_65_2.png
│   ├── ipad_129_1.png
│   └── ...
```

**Supported display types:**

The display type is chosen from the image dimensions, so iPhone, iPad, Apple
Watch, Apple TV, Mac and Apple Vision Pro screenshots exported at App Store
sizes are classified without any naming convention:

* iPhone 6.9", 6.7", 6.5", 6.1", 5.8", 5.5", 4.7", 4" and 3.5"
* iPad Pro 12.9"/13", iPad Pro 11", iPad 10.5" and iPad 9.7"
* Apple Watch Ultra, Series 10, Series 7, Series 4 and Series 3
* Apple TV, Mac and Apple Vision Pro

A device name in the file name overrides the dimensions, for example
`vision pro`, `apple tv`, `mac`, `watch ultra`, `watch series 10`,
`ipad pro 13` or `iphone 6.5`. Apple TV 4K and Apple Vision Pro share the
3840x2160 size, so those files must carry `apple tv` or `vision pro` in the
name. A screenshot whose size matches no display type fails the command instead
of being uploaded to a guessed slot.

## Partial Imports

`migrate import --confirm` applies version localizations, App Info
localizations, review information, and screenshots in that order. When a step
fails after earlier changes already reached App Store Connect, the command still
writes the result document to stdout and exits non-zero:

```json  theme={null}
{
  "status": "partial",
  "failureStage": "version_localizations",
  "failure": "migrate import: failed to update ja: ...",
  "uploaded": [
    { "locale": "en-US", "action": "update", "localizationId": "loc-en" }
  ]
}
```

`completedStages` lists the stages that finished before the failure and is
absent when none did, as above, where the failure happened inside the first
stage.

A failure before the first change prints nothing to stdout and only reports the
error, so an empty stdout means nothing was applied. Review information that
already matched and screenshots that already exist are not changes, so a failure
after them is a plain error too. The screenshot stage can still create a
localization for a screenshot-only locale before it fails with nothing to
report; that locale is named on stderr:

```
Warning: created localization "fr-FR" before the failure; re-run import or remove it manually
```

## Locale Normalization

Fastlane uses directory names like `en-US`, `es-ES`, `ja`, etc. The CLI automatically normalizes these to App Store Connect locale codes:

* `en-US` → `en-US`
* `es-ES` → `es-ES`
* `ja` → `ja`
* `zh-Hans` → `zh-Hans`
* `zh-Hant` → `zh-Hant`

## Skipped Items

The import command reports directories and files it did not read. Directory
names that are not locales, symlinked entries, unsupported screenshot files, a
missing conventional directory, and anything a Deliverfile or flag turned off
all appear here (`metadata/review_information` and `metadata/default` are read
as part of the import and are not reported):

```json  theme={null}
{
  "skipped": [
    {
      "path": "fastlane/metadata/trade_representative_contact_information",
      "reason": "skipped non-locale directory \"trade_representative_contact_information\": locale \"trade_representative_contact_information\" must match pattern like 'en', 'en-US', or 'zh-Hans'"
    },
    {
      "path": "fastlane/screenshots",
      "reason": "skipped by --skip-screenshots"
    }
  ]
}
```
